# Images 架构审查与优化

审查模型：GPT-6 Astra，High。用户授权范围：审查整个 Images 功能、评估意见并执行优化。审查基线为 `3741506`；本轮不升级版本或发布。

## 审查结论

现有分层方向值得保留：图片提示词选择使用内部事实，原生消息树解析留在 Codex Adapter；本地索引以精确 ID 读取文件，云端引用绑定账号、用户和内容指纹；Runtime Host 只组合、鉴权和转发。原生 React 呈现必须留在专有 Adapter，不应为了目录对称而移入普通业务代码。

第二轮复核发现：首次画布能力加载期间切换来源，图库实例仍存活，账号／卸载检查不足以阻止旧画布打开。已增加打开请求版本，来源切换、列表加载重置与卸载均使待完成请求失效；View prompts 也只在画布成功打开后继续。

## 保留的行为与约束

- 浏览不上传；用户显式收藏／文件夹操作才进行 Library 登记。
- 上传成功后的身份必须持久保存，即使发起界面已经卸载；UI 回写与持久结果分别处理。
- 上传结果不确定时保留预留状态，不盲目重传，避免创建重复云端副本。
- Chat about this 的导航会合法卸载图库；向 Chat 面板移交时继续检查功能 signal、账号和可见原生 Composer，而非把全部 `disposed` 都当作取消。
- 不改原生画布、菜单、卡片、比例、Zoom to fit、底部 Composer 与 Comment 显隐契约。
- 历史 `web/` 服务与日志索引仍有实际入口或复用，不作整片删除；不新建通用能力注册框架。
