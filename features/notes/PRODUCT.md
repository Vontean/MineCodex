# Product

## Register

product

## Users

CodexNotes serves individual, frequent Codex users who move among Projects, Tasks, and windows while keeping lightweight personal material close to the current conversation. Their primary jobs are remembering unfinished work, reusing short prompts or excerpts, and attaching known local files without leaving the active Codex workflow.

## Product Purpose

CodexNotes is a local-first personal call layer for Todo, Prompts, and pinned Files. It succeeds when those materials remain quickly reachable across Codex contexts while the product stays simpler than a knowledge base, task manager, or asset-management system. Host integration may fail independently, but local data and source files must remain safe.

## Brand Personality

Native, quiet, and direct. The interface should feel like a restrained part of Codex: familiar enough to disappear into the task, explicit about what each action does, and free of ornamental product chrome.

## Anti-references

- A standalone admin dashboard visually embedded inside Codex.
- A card-heavy team task manager with dates, reminders, assignment, or automation.
- A cloud knowledge base with folders, tags, search, AI classification, or collaboration UI.
- A custom visual system that merely approximates Codex instead of consuming its current semantic tokens and interaction conventions.

## Design Principles

1. Stay in the current workflow: material should be reachable without leaving the active Codex Task.
2. Earn native familiarity: reuse Codex structure, tokens, type, controls, and behavior wherever the host provides a reference.
3. Keep lightweight actions lightweight: reveal only the controls needed for the current section and avoid page-level ceremony.
4. Preserve user control: never auto-send, auto-create, auto-complete, or silently reinterpret personal material.
5. Keep failure boundaries safe: integration failures must not damage local data, pinned source files, or unrelated Codex behavior.

## Accessibility & Inclusion

Use semantic controls, accurate accessible names, keyboard-visible focus, sufficient contrast, reduced-motion handling, and live theme-token updates. Light, dark, custom accent, and high-contrast changes must retain understandable state without relying on color alone.
